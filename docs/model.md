# Словник полів моделі позиції

Назви в колонці `name` стабільні. Їх без змін використовують розмітка форм, валідація JavaScript, типи TypeScript і ключі JSON під час обміну з API.

| Поле | name | Тип даних | Елемент | Обмеження |
| --- | --- | --- | --- | --- |
| Назва | `title` | рядок | text | required, minlength 2, maxlength 80 |
| Артикул | `sku` | рядок | text | required, pattern `^[A-Z]{2}-\d{3}$`, maxlength 6 |
| Зображення | `image` | файл або ім'я файлу | file | accept SVG, WebP, PNG; у даних каталогу – лише ім'я файлу |
| Альтернативний текст | `imageAlt` | рядок | — | required; описує зображення, не назву позиції |
| Категорія | `category` | рядок | select | required; перший пункт порожній |
| Ціна | `price` | число | number | required, min 1, max 9999, step 1 |
| Об'єм або вага | `volume` | число або `null` | number | min 1, max 1000, step 1; без `required`, бо для десерту поле порожнє |
| Дата додавання | `addedAt` | дата | date | required, min 2024-01-01, max 2027-12-31, формат `РРРР-ММ-ДД` |
| Опис | `description` | рядок | textarea | required, maxlength 300 |
| Наявність | `inStock` | логічне | checkbox | value `true`; знятий прапорець не надсилається |
| Ідентифікатор | `id` | рядок | hidden | лише форма редагування і адреса `details.html?id=` |
| Порції | `sizes` | масив об'єктів | — | щонайменше один розмір; поля нижче |

Значення `category`: `coffee`, `tea`, `dessert`, `seasonal`.

`volume` – ціле число без одиниць: мілілітри для напоїв або грами для десертів. Значення `null` означає, що картка показує лише ціну.

Поле `image` у даних каталогу і в запиті get передає лише ім'я файлу, не вміст.

`imageAlt` не виводиться з `title`: це окремий опис вмісту зображення.

Кожен елемент `sizes`:

| Поле | name | Тип | Зміст |
| --- | --- | --- | --- |
| Назва порції | `name` | рядок | заголовок рядка таблиці |
| Об'єм або вага | `volume` | число | без одиниць |
| Одиниця | `unit` | рядок | `мл` або `г` |
| Ціна | `price` | число | гривні |
| Калорійність | `calories` | число | кілокалорії |

## Вбудовані обмеження і власні правила

Вбудовані обмеження лишаються в розмітці. Власні правила – чисті функції в `js/validators.js`: вони отримують значення й контекст і не читають DOM. Поточна дата передається як `context.today`.

| name | Вбудовані обмеження | Власне правило |
| --- | --- | --- |
| `title` | required, minlength 2, maxlength 80 | після `trim` від 2 до 80 символів; назва унікальна після нормалізації (`trim`, нижній регістр, один пробіл замість кількох). Позиція з `context.currentId` не вважається дублікатом |
| `sku` | required, maxlength 6, pattern `^[A-Z]{2}-\d{3}$` | немає; пояснення формату береться з `data-pattern-message` |
| `image` | accept SVG, WebP, PNG; поле не обов'язкове | немає |
| `imageAlt` | у формі немає | для нової позиції в попередньому перегляді – «Фото позиції меню»; під час редагування зберігається попередній опис |
| `category` | required, перший пункт порожній | немає окремого правила; значення категорії входить у контекст правила `volume` |
| `price` | required, min 1, max 9999, step 1 | немає; текст діапазону збирається з `min` і `max` |
| `volume` | min 1, max 1000, step 1 | обов'язковий для `coffee`, `tea`, `seasonal`; для `dessert` має бути порожнім (`null` у моделі) |
| `addedAt` | required, min 2024-01-01, max 2027-12-31 | дата не пізніша за `context.today` |
| `description` | required, maxlength 300 | після `trim` від 1 до 300 символів, тож рядок із самих пробілів не проходить |
| `inStock` | checkbox, value `true` | немає; відсутність у `FormData` дає `false` |
| `id` | hidden, лише форма редагування | немає |
| `sizes` | у формі немає | під час редагування копіюється з позиції; для нової позиції – порожній масив |

## Поля відгуку

Ці поля не входять до позиції каталогу. Їхні назви стабільні для форми на сторінці деталей.

| Поле | name | Вбудовані обмеження | Власне правило |
| --- | --- | --- | --- |
| Ім'я | `authorName` | minlength 2, maxlength 80, не обов'язкове | якщо заповнене – від 2 до 80 символів після `trim` |
| Пошта | `email` | required, type email, maxlength 80 | немає; окремі тексти для порожнього значення і неправильного формату |
| Телефон | `phone` | pattern `^\+380\d{9}$`, maxlength 13, не обов'язкове | немає; шаблон застосовується лише до непорожнього значення |
| Оцінка | `rating` | required на групі перемикачів | «Оберіть оцінку», текст біля `fieldset` |
| Солодкість | `sweetness` | range, min 0, max 5, step 1, value 2 | немає |
| Коментар | `comment` | minlength 10, maxlength 500, не обов'язковий | якщо заповнений – від 10 до 500 символів після `trim` |
| Згода | `consent` | required, value `yes` | немає окремої функції; порожнє значення пояснює, що потрібна згода з правилами публікації |
